# SRM 前后端业务开发

## 项目与源码

- 后端：D:/prjs/jvav/srm-project
- 前端：D:/prjs/Front-End/srm-FE
- 后端：Java 21、Spring Boot、Spring Data JPA、MySQL、Redis、Gradle。
- 前端：React、TypeScript、Umi Max、Ant Design、Pro Components、npm。

开始工作时读取涉及仓库的 AGENTS.md 及其引用文件。
TECHNICAL_OVERVIEW.md 用于定位模块；技术实现以当前源码和构建配置为准。
业务实现与本 skill 已确认规则不一致时，按当前需求修正相关部分，并说明差异。

## 工作范围与边界检查

根据需求定位后端 Controller、Service、Repository、Entity，以及前端页面、service、类型定义、路由和权限配置。
复用所属业务模块的已有实现。单端任务仅在接口契约或业务行为受影响时检查另一端，不重构无关模块。

实现业务操作前，检查相关的状态限制、数量与金额约束、关联数据、权限、重复提交、请求重试、并发修改、文件上传及多语言显示。
已确认规则直接执行。缺失且影响当前需求正确性的业务规则，应向用户确认。
技术实现细节依据项目约定选择，不自行补充业务限制。

## 接口契约

实现前明确 HTTP 方法、路径、查询参数、请求体、响应字段、可空性、关联对象、分页结构、日期、金额、ID、状态码、文件地址、认证和错误响应。
多语言字段应明确返回方式及语言选择位置。

后端统一结果结构为 code、msg、data、errorCode、errorMsg。
检查前端请求层如何解析结果，避免重复解包或吞掉业务错误；区分 HTTP 失败与 Result 业务失败。

前端开发代理把 /api/* 转发到 localhost:9090，并去掉 /api 前缀。
例如 /api/products 对应后端 /products。部署环境应检查实际 API 配置，不能依赖开发代理。

## 多语言业务字段

商品及其他业务 Entity 中，以 _zh、_pl 等语言后缀结尾的字段，表示同一业务属性的不同语言版本。
例如 name_zh、name_pl 表示中文与波兰语名称，description_zh、description_pl 表示对应语言的说明。
数据库、Java Entity 和接口 JSON 的命名可能不同，应检查实际映射。

普通业务展示根据用户系统默认语言选择对应字段：中文取 _zh，波兰语取 _pl，其他语言按实际支持字段映射。
从项目已有用户语言设置或国际化机制获取语言，核对 zh-CN、zh-TW、pl-PL 等 locale 的映射，复用已有实现。
该规则适用于列表、详情、选择器、表格、提示等展示；语言切换后同步更新，避免旧语言缓存。

业务多语言字段不是静态翻译键；菜单和按钮等文案继续使用项目国际化资源。
显示某个语言版本不意味着覆盖其他语言字段。编辑时明确修改哪些语言字段，保留未修改版本，不能将显示值写入所有语言字段。
目标语言为空或不存在时沿用已有回退规则；无规则且当前功能依赖时确认，不自行选择回退语言。
按现有架构选择前端解析或后端本地化，避免重复选择。涉及搜索、排序或导出时核对语言行为。
合同遵循下文固定中文规则，不随用户系统语言变化。

## 文件与图片

业务属性中表示文件的字符串字段用于上传文件，例如实物图、logo 图。
前端提供文件选择、上传及适用的预览能力。业务数据库字段保存上传后的文件地址，不保存二进制或 Base64 内容。
根据业务含义识别文件字段，不能把所有字符串都当成文件。
业务提交使用成功上传的地址；编辑时未替换文件应保留已有地址。

检查现有上传接口与存储实现。文件元数据 CRUD 不等于实际上传能力；当前需求需要且缺少时补齐上传链路。
类型、大小、访问方式、存储位置沿用已确定配置；缺少且影响功能时确认。
替换文件不意味着自动删除可能被其他记录引用的文件。

## 商品与 SKU

一个颜色的商品对应一个 SKU。
部分 SKU 包含多个商品，不能假设 SKU 与商品永远一一对应。组合 SKU 应有能够表达商品组成的关系。
生成合同时，将组合 SKU 包含的商品展开为多行合同明细，核对组成商品数量、单位、价格与金额。
组合 SKU 的数量换算和价格分配规则尚未确定，当前需求涉及时确认，不能自行平均分配价格。
普通商品名称和说明展示遵循用户系统语言规则，合同使用中文。

## 询价标识与报价来源

询价由批次与 SKU 共同确定。一个批次可以包含多个 SKU，例如“10 月份第一单”可包含 O756、S214。
区分询价业务标识（批次 + SKU）与该询价下的报价来源（店铺、联系人）。
不能将同批次不同 SKU 当成同一个询价，也不能仅凭批次判断重复转单。

## 重新询价与询价历史

允许重新询价并修改询价信息。
在同一批次、同一 SKU 下：
- 店铺相同或联系人相同，视为同一个询价来源，更新已有记录，不新增询价历史记录。
- 店铺和联系人均不同，视为新的报价来源，在询价历史表中新增记录。

询价历史表保留不同报价来源，不保存同一来源每次修改前的快照。
重复提交、请求重试和并发更新应避免重复来源记录。
使用可靠身份标识判断店铺或联系人相同，不仅凭可能重名的展示文本；缺失值不能直接视为身份相同。
若店铺匹配一条记录而联系人匹配另一条，不能任意选择或自动合并，遇到时确认冲突处理规则。

## 询价转订单

同一个询价不能重复转订单。按批次 + SKU 检查已有转单，不能通过新增报价来源绕过限制。
转单数量不能超过询价数量，核对数量单位与业务含义。
转单成功后，询价状态变为 ORDER。
订单创建与询价状态更新应保持一致，检查事务边界。

连续点击、并发请求或请求重试不得生成重复订单。前端提交状态控制不能替代后端校验和并发保护。
按现有模型选择事务、锁、唯一约束或幂等机制，保证并发下约束有效。
已处理请求应返回明确且可由前端正确处理的结果。
同一询价有多个报价来源时，按已确定选择规则采用来源及数量，不能自行选择最低价或第一条。

## 关闭订单

订单可以随时关闭，表示需要重新询价或取消此次询价下单。
不能自行增加某阶段禁止关闭的业务限制；关闭不等于删除。
以下规则仅在当前功能依赖时确认：
- 关闭后的询价状态及重新询价与取消下单的区分。
- 关闭后能否再次转单，以及与不能重复转单的关系。
- 关闭对已有合同、收货、付款的影响。

不能自行将关闭解释为自动恢复转单资格。

## 合同生成与修改

生成合同检查订单、SKU 和组成商品关系，组合 SKU 生成多行明细。
已签署合同允许修改，例如更换箱子后重量和体积变化，不能仅因签署而禁止修改。
修改保持相关字段和计算结果一致，不把允许修改包装信息扩大为任意修改所有字段的授权。
当前需求涉及时确认具体可修改字段、是否重新签署、版本或变更记录处理，以及对金额、物流、收货、付款的影响。

## 合同语言

合同生成、预览、打印、导出一律使用中文，不随用户系统默认语言或语言切换变化。
商品名称、说明等统一取 _zh 对应中文字段，核对 Entity 与 JSON 实际映射。
组合 SKU 展开的每行明细均使用中文商品信息。
合同签约快照中的名称、说明保存中文，查看者切换语言不改变正文或已保存快照。
缺少中文内容时，不自动用其他语言替代，应提示补充；具体提交或生成限制依据当前需求确认。

## 后端实现

沿用所属模块现有 Controller → Application Service / Domain Service → Repository 分层。
新增输入优先使用 DTO 与 Jakarta Validation。按需求使用 DTO/VO 返回，避免无意暴露实体关联或递归序列化。
状态流转、数量金额约束、关联校验由后端执行，前端校验不是唯一保障。
跨实体写入检查事务；并发约束必须在实际写入路径有效，不能仅依赖写入前查询。
修改持久化字段或关联时，核对实体、SQL 脚本和 Hibernate DDL 配置。
明确多语言存储及接口映射，单语言更新不清空其他版本。
检查认证授权；按钮隐藏不能替代后端访问控制。

## 前端实现

检查 src/services/srm/api.ts 和相关页面，复用适合契约的请求方式。
明确业务字段使用具体 TypeScript 类型，不扩大 Record<string, any> 的使用。
新增页面核对 config/routes.ts、菜单国际化、src/access.ts 和访问控制。
表单约束与后端一致，提供加载、空数据、失败反馈与提交状态。
文件字段使用上传控件和地址预览；普通多语言字段复用公共语言选择逻辑，合同固定中文。
状态变化成功后刷新相关数据，包括转单后的 ORDER 状态。
按前端仓库约定查询 Ant Design 组件 API，按约定维护生成文件。
联调检查 mock 是否拦截接口。cloudflare-worker 是独立工程，仅需求涉及时修改。

## 验证

按改动范围选择检查：
- 后端目录：.\gradlew.bat test；必要时 .\gradlew.bat build。
- 前端目录：npm run lint；必要时 npm run test、npm run build。
- 涉及组件或提交时执行仓库要求的其他检查。

针对改变的行为验证相关场景：
- 普通业务展示跟随中文、波兰语及语言切换，缺翻译遵循确定的回退规则。
- 修改一种语言不覆盖其他版本。
- 合同在任何系统语言下生成、预览、打印和导出均为中文。
- 上传后保存文件地址，未替换时保留原地址。
- 同批次不同 SKU 独立处理。
- 同店铺或同联系人报价更新原记录，不增加历史条数。
- 不同店铺且不同联系人新增历史记录。
- 数量超限拒绝转单，成功转单后状态为 ORDER。
- 连续点击、重试或并发不生成重复订单。
- 关闭符合确定规则，签署合同可完成允许的修改。
- 组合 SKU 生成对应多行中文合同明细。

跨端确认请求实际进入 Spring Boot，字段、响应解析、保存后展示一致。
缺少数据库、Redis、文件存储等条件时，明确未完成的验证，不把编译通过当作联调成功。
